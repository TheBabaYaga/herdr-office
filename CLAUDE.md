# herdr-office

herdr-office is a local web page that shows herdr agents as workers in a 3D voxel office. `bridge.mjs` polls the herdr socket and streams the snapshot to the browser. The files in `public/` turn the snapshot into rooms (workspaces), pods (tabs), and desks (panes) with three.js.

Read these files for more context:

- `INTENT.md`: why the project exists, the decisions of the user, the features that the user cut, and the open items.
- `docs/herdr-agent-model.md`: how herdr models agents, statuses, and the socket protocol. Its section 6 is an early design. Where it differs from the code (event subscription, the `herdr` CLI for actions), the code and `INTENT.md` are correct.
- `docs/README.md`: the index of the docs: which doc to read for a task, the data flow, and a glossary.

Read the doc for the area that a task touches before you read the code. When a change makes a doc line wrong, fix that line in the same change.

## How the main session works here

The main session orchestrates. It plans the work, briefs subagents and workflows, and verifies the result. It does not write project code itself. Use the model that the user names for an agent.

A brief for a code agent gives:

- the files and the functions that the agent owns,
- the result that the agent must deliver, and the check that proves it,
- the safety rules in this file.

`public/office.js` is the file that most tasks touch. When two or more agents edit it at the same time:

- Give each agent its own region: one or more named functions, for example `build`, `desk`, `worker`, `pose`, `declutter`, `update`, `hud`, or `fill`.
- Tell each agent to use small `Edit` calls. An agent must not `Write` the full file.
- Tell each agent to read its region again before each `Edit`. Another agent can change the file between two edits.

The same rules apply to `public/decor.js`. After the agents finish, the main session runs the checks in the next section.

## Where work files go

- `.local/` holds the work files of an implementation: specs, plans, and other notes for a task. Git ignores it.
- Save a new plan in `.local/plans/` and a new spec in `.local/specs/`. Do not use `docs/superpowers/` for new files.
- A new git worktree does not get `.local/`, because Git ignores it. Run a session that executes a plan in this checkout, or copy the plan into the worktree.
- Save each IDR (implementation decision record) in `docs/idr/`. Git tracks that folder. An IDR records a technical choice made during an implementation. The decisions of the user stay in `INTENT.md`.

## Run and check

```sh
npm start                       # the bridge on http://127.0.0.1:4747/ (PORT=<n> for another port)
npm test                        # node --test test/*.test.mjs
node --check public/office.js   # a syntax check only: three.js loads in the browser
npm run build                   # dist/herdr-office and its tar (see docs/release.md)
```

- Add `?demo` to the URL (`http://127.0.0.1:4747/?demo`) to see simulated agents. The demo page opens no `/events` stream, so the bridge does not poll herdr.
- `npm test` uses a glob. On Node 25, `node --test test/` reads `test/` as a module path and fails with "Cannot find module". Node 26 accepts it, but keep the glob.
- `node --check` checks one file. It ignores a second file argument, so run it once for each changed file in `public/`.
- The bridge starts from `if (import.meta.main)`. On a Node version without `import.meta.main`, `npm start` exits and starts nothing. The repo runs on Node 26.
- The repo has no npm dependencies and no lockfile. Keep it that way. three.js 0.186.1 comes from jsDelivr through the importmap in `public/index.html`.
- A new three.js addon import needs its URL and its sha384 hash in the importmap `integrity` block. Get the hash with `curl -s <url> | openssl dgst -sha384 -binary | openssl base64 -A`. Write the value as `sha384-<output>`.

Contracts between the files:

- `buildOffice(snapshot, meetings = [], prev = null)` returns `{ rooms, desks, counts, subagents, focus, bounds, corridors, terraces, entrance, games }`.
- Each room has `games: [{ kind, x, z, places }]`, in world coords. It is `[]` except in a big workspace room or a big party room. A room is big when `w * d` minus the area of its pods is 80 m² or more. A big room gets a ping-pong table and a chess table if both fit, else the one that fits (`games()` in `model.js`). `kind` is `pingpong` or `chess`. `places[0]` stands west of the table (`rot` 3, faces +x) and `places[1]` east (`rot` 1, faces -x), at the table z: 0.62 from the center for chess, 1.55 for ping-pong. A place is the pivot of a player, as a kitchen chair point is. The table stands on either side of the main walk line of the room (`mainZ()`: the lane of the pod row nearest to the door, or the party strip), off the pods, the lamp posts, the door area, the dance floor, the booth, the walk rects, and the other table, with a pad of 0.3. The main walk line then reaches the x of each place, and a lane runs from it to each place. These rects go into `room.walk`. `office.games` lists every table in `rooms` order as `{ room, kind, x, z, places }`. Table `t` is `office.games[t]`.
- A room has `id`, `kind`, `label`, `number`, `status`, `x`, `z`, `w`, `d`, `door: { x, z, side }`, and `pods`. `kind` is `workspace`, `meeting`, `kitchen`, `party`, or `lobby`.
- A workspace room, the kitchen, and the party room also have `walk: [[x0, z0, x1, z1], ...]`. These are world rects of the free floor that the idle routes use outside the pods. `placer()` in `decor.js` keeps each prop off them. In the kitchen, the strip rect reaches each chair x, and a lane runs from the strip to each chair point. So each kitchen chair stands on its own lane.
- The party room (id `party`, label `Party`) fills the spare width of the row with the most spare width, if that width is 7 or more. The spare width is the building width minus the normal widths of the rooms in the row. On a tie, the first row wins. The party room is the last room of its row, or the room just before the lobby. The other rooms of its row keep their normal width. Without such a row, the office has no party room. `rooms` keeps the row order, so the lobby stays `rooms.at(-1)`.
- Each other row with a spare width of 4 or more keeps the normal width of each room. A terrace `{ id, x, z, w, d }` fills the spare width at the east end of the row, with the row depth. It reaches from the east wall of the last room to the cross corridor. Its id is `terrace:<row index>`. Each other row stretches its rooms to the building width. `terraces` is `[]` when no row has a terrace. A terrace is not in `rooms`: it has no door, no sign, no pods, and no walk rects, and nobody walks there.
- The party room also has `spots`, `floor`, and `booth`, in world coords. Let `s` be +1 for a south door and -1 for a north door, `cx` the room center x, and `zm` the room center z. The front row of `spots` stands at `zm + 0.5 s`, 2.0 apart and centered, with `floor((w - 3) / 2) + 1` spots. The back row stands at `zm - 0.5 s`, with one spot less, each 1.0 from its two front neighbors. `spots` holds the front row first (west to east), then the back row. The strip (the walk line in front of the floor) is at `zm + 1.5 s`, so it is `d / 2 - 1.5` from the door wall. `floor: [x0, z0, x1, z1]` reaches 1.0 past the outer front spots in x, and from the strip to 1.0 behind the back row in z, in whole 1 x 1 tiles. `booth: { x: cx, z: zm - 2.1 s, rot }` is the DJ booth center, and `rot` (0 for a south door, 2 for a north door) turns its front to the door. Its `walk` holds the door rects, the door lane to the strip, and one rect over the strip and the spots.
- The kitchen also has `counter: { x, z, len }` (world coords of the counter origin on the north wall, and its length) and `spots: [{ x, z }]` (at least 3 standing spots in front of the counter, at least 0.85 apart, each facing -z). `kitchen()` in `decor.js` draws the counter from `room.counter`.
- The kitchen also has `tables: [{ x, z }]` and `chairs: [{ x, z, rot, table }]`, in world coords. A table is a cafe table with two crossed tops (0.9 x 0.6 and 0.6 x 0.9) at (x, z). The tables stand `off` west and east of the room middle, 0.3 south of it. `off` is 1.3 for a north door, so the camera sees an eater over the east wall. `off` is 2.1 for a south door, so the door lane passes between the tables. A chair point is the pivot of a seated worker, where a lunch route ends. A chair stands 0.8 west (`rot` 3, faces +x) or 0.8 east (`rot` 1, faces -x) of `tables[table]`, at the table z. The worker faces -z before the turn (`rotation.y = rot * PI / 2`). `kitchen()` draws a wooden chair 0.1 behind each chair point, as the desk chair stands behind the worker pivot. It draws the tables and chairs without `put()`, because each chair is on a walk rect, and it adds their footprint to `put.taken`.
- `route(office, deskId, spot, to = 'kitchen')` returns `[[x, z], ...]`: the way from the worker seat `(d.x, d.z + 0.4)` to a spot in the room with the id `to` (`'kitchen'`, `'party'`, or the id of the room of a game table). A lunch route is `route(office, deskId, chair, 'kitchen')`: along the strip to the chair x, then straight to the chair point. A game route is `route(office, deskId, place, roomId)`, with the room of the table: along the main walk line of that room to the place x, then straight to the place. A desk in the room of the table does not cross the door: it goes along the door lane to the main walk line. All segments are axis-aligned. The route first steps 0.65 to the side of the chair, then uses the lane behind the desk row, goes round the pod on its east side (the lamp post stands on the west side), passes the door on the free side of the open leaf (it crosses the wall 0.145 off the door center, then steps aside 0.33 into the room, so a body clears the post and the leaf tip), keeps its lane 1.4 or more from the door wall, follows the corridor center lines, passes the door of the target room in the same way, walks a strip in that room, and ends at the spot. In the kitchen the strip is 1.9 from the north wall. The spots are 1.35 from the wall, so a walker keeps 0.55 from each other worker at the counter. In the party room the strip is `d / 2 - 1.5` from the door wall (`partyZ()`), 1.0 in front of the front row of dance spots. A walker to a back spot passes 1.0 from the front spots.
- `season(date)` returns `'halloween'` from 24 October to 1 November, `'winter'` from 1 December to 6 January, else `null`, by the local month and day. `office.js` reads `?season` (any value, for example `none`, replaces the date) and checks the date once a minute, because the bridge sends nothing while herdr does not change. Each `DECOR` function and `terrace()` take `(g, room, season)`. Only `'halloween'` and `'winter'` have props. Halloween: two pumpkins by the reception in `lobby()`, a small pumpkin on the counter of `kitchen()`, four bats round the disco ball in `party()`, and a web in the north-west corner of `workspaceDecor()`. Winter: a tree in `lobby()`, about a third of the `tree` props of `furnish()` become `xmasTree` (chosen by the spot, so each build gives the same trees), and `terrace()` puts a snow cap on each green block that is 0.1 high or more. The terrace grass and the hedge get snow in `build()`. With Halloween, each room function (`workspaceDecor`, `kitchen`, `meeting`, `party`, `lobby`) returns `{ x, z }` in world coords (the spot of the room candelabra from `candleSpot()`) or `null`. Else it returns `undefined`. `meeting(g, room, season)` takes the season too.
- `snowflakes(t)` returns `[{ x, z, phase }]` for a rect `{ x, z, w, d }`: a jittered grid, with `cols = max(1, round((w - 0.6) / √2))` and `rows = max(1, round((d - 0.6) / √2))`, so each cell is about 2 m². Each cell holds one flake at a random point of the cell, each 0.3 or more from each rect edge. `phase` is random in [0, 1). The random source is `rng(hash("x,z,w,d", 1e9))`, so the same rect always gives the same flakes. Two flakes can lie close together. `flakeAt(f, s)` returns `{ x, y, z }` for the time `s` in seconds. `y` falls from 2.6 at 0.3 a second (one fall takes about 8.7 s), then starts again at the top. `x` drifts by up to 0.1 (`0.1 * sin(s + 6 * phase)`). `z` stays. A flake stays 0.2 or more inside the terrace edges.
- `twinkle(ph, t, amp = 1)` returns the halo opacity of one tree bulb at the time `t` in seconds: `0.35 + 0.25 * amp * sin(1.5 * t + ph)`. With amp 1 it goes from 0.1 to 0.6 in about 4.2 s. With amp 0.5 (reduce motion) it goes from 0.225 to 0.475.
- `outdoors(bounds)` takes `office.bounds` (`{ w, d }`) and returns 4 rects `{ x, z, w, d }` (north, south, west, east) in a band round the slab. The slab reaches P = 0.3 past each building edge. The band width is M = `Math.max(w, d) / 2 + 3`. North is `{ x: -P - M, z: -P - M, w: w + 2P + 2M, d: M }`, south is `{ x: -P - M, z: d + P, w: w + 2P + 2M, d: M }`, west is `{ x: -P - M, z: -P, w: M, d: d + 2P }`, and east is `{ x: w + P, z: -P, w: M, d: d + 2P }`. The rects do not overlap each other or the slab. `snowflakes()` and `flakeAt()` work on them as on a terrace, so a flake stays 0.2 or more outside the slab.
- `candleSpots(office)` returns `[{ x, z, axis }]`, the corridor candelabra, deterministic. A spot lies every 4 along each corridor from 2, in turn on its two edges, 0.4 in. `axis` is `'z'` in the cross corridor, else `'x'`. It drops a spot within 1.3 of a door center on the same edge. For a north door it also drops the spots from 3.0 west to 1.3 east of the door on both edges, so no door sign covers a candelabra. It drops a spot in the cross corridor within 0.4 of a band corridor mouth. No route passes within 0.5 of a spot.
- `lightningPlan(rand = Math.random)` returns `{ wait, flashes: [{ at, len, power }] }`: a wait of 20 to 60 s, a first flash at 0 (power 1, 0.08 to 0.12 s), and in half of the plans a second flash 0.3 to 0.6 s later (power 0.6). `flash(plan, s)` returns the power of the flash that holds the time `s` after the strike start, else 0.
- `rng(s)` returns a function that gives a seeded number in [0, 1) at each call (mulberry32). `ghosts({ w, d })` returns 3 ghosts, deterministic from the bounds and the ghost index. A ghost is a closed loop of 8 points `{ x, z, hover }`: `x` in [1, w - 1], `z` in [1, d - 1], and `hover` in [2, 5] s. `ghostAt(g, s)` returns `{ x, y, z, dx, dz }` at `s` seconds. The ghost floats at 0.8 a second in a straight line to the next point, and hovers there for `hover` s. After the last point it floats to point 0, and the loop starts again. `dx, dz` is the unit direction of the current leg, and of the last leg during a hover. `y` is the base of the ghost: a bob from 0.3 to 0.4 in 2 s.
- `daylight(min)` returns `{ dir, sun, sunPower, ambient, ground, ambientPower, window, windowGlow, background }` for `min` minutes since local midnight (modulo 1440). Colors are `#rrggbb`, and `dir` points from the building center to the sun. It blends the keys 06:00 and 21:00 (night, `sunPower` 0), 08:00, 13:00, 15:00 (the reference day look, decision 9), and 18:00 in a cycle.
- `office.js` builds the corridor candelabra in `build()` only with `season === 'halloween'`, like the room candelabra.
- `calm(dist)` returns 0 up to 1.4 from the nearest door center and 1 from 2.0. `stroll()` in `office.js` multiplies the arm swing by it, and the mug hand angle is `0.1 + 1.1 * calm`. Near a door the arms hang, so no hand goes through the open leaf or a post.
- `opens(office, d, a)` returns the ids of the rooms whose door the walker of desk `d` opens, with `a = { x, z, phase, room }` (from `breaks()`). `room` is the id of the target room. It returns only the room of `d` and the room `a.room`, and only within 3 of the door center. In the phase `stay` it returns `[]`. A walker whose target is its own room (a game table there) opens no door. A walker in a corridor opens no other door. A party walker does not open the kitchen door, and a kitchen walker does not open the party door.
- `along(path, s)` returns `{ x, z, dx, dz }`: the point at distance `s` (clamped) and the unit direction of its segment.
- `pathLen(path)` returns the length of a polyline. Use it for each route length.
- `stepBreak(trips, claimed, id, { idle, seed, spots, route, tables }, t)` keeps the trip state of one worker, once a frame. `trips` maps a desk id to `{ n, next, trip }`, and `claimed` maps the key `'<kind>:<index>'` of a spot (for example `'lunch:2'`) to a desk id. `spots` holds the spot count of each kind, `{ kitchen, lunch, party }`: the counter spots, the kitchen chairs, and the dance spots. A missing or 0 count means that the office has no such spot. `tables` holds the kind of each game table, `office.games.map((g) => g.kind)`. The kind `game` has `2 * tables.length` places: place `2t` and `2t + 1` belong to table `t`, with the key `'game:<i>'`. A game place counts as free only at a table where both places are free. `route(kind, i)` gives the path to spot `i` of `kind`. When a trip starts, the worker first looks for a waiter: a worker alone at a table, with no partner and no rush, in its first `WAIT` (20) s after its arrival. It takes the other place of that table, whatever its own pick is. Else `breakPlan(seed, n).pick` picks the first kind: `kinds[Math.floor(pick * kinds.length)]`, where `kinds` holds the kinds of `['kitchen', 'lunch', 'party', 'game']` that have spots. If that kind has no free spot, the worker tries the other kinds in that order. If all are full, it keeps browsing. The trip has `room` (the kind) and `spot` (its `claimed` key). A lunch trip stays `plan.lunch`, a waiter stays `WAIT`, and each other trip stays `plan.stay`. A game trip also has `table`, `partner` (a desk id or `null`), `begin`, and `end`. At a join, both trips get `partner`, `begin` is the later arrival, `end` is `begin` plus the game time from the plan of the waiter (chess 30 to 60 s, ping-pong 20 to 40 s), and both stays end at `end`. A rush or `endBreak()` of one player before `end` ends the game of the other: its `end` becomes `t` and its stay ends at `t` or at its arrival, and it walks back. After `end` it changes nothing. `breaks()` in `office.js` gives `opens()` the room id `kitchen` for a lunch trip and the room of the table for a game trip. It returns `{ s, phase, got, play, trip }` for a worker on a trip, where `play` is true in the stay between `begin` and `end`, and `null` for a worker at the desk. `got` (the mug) turns true in the stay of a kitchen trip only. It claims the spot when the trip starts and frees it when the trip ends. After a rush it drops the state, so the next idle stretch starts with `n` at 0. `endBreak(trips, claimed, id, t)` drops the state of a desk, frees its spot, and ends the game of its partner. It needs the frame time `t`.
- `tripAt({ len, start, stay, rush? }, t)` returns `{ s, phase }`. `phase` is `out`, `stay`, `back`, `rush`, or `done`. `WALK` is 1.6 and `RUN` is 4 (units a second). `rush` is the time when the status left idle. The worker then runs back from its place.
- `breakPlan(seed, n)` returns `{ wait, stay, lunch, pick, game }`: the browse wait before trip `n` in seconds (5 to 30 for the first, 20 to 60 for the next ones), the stay in seconds (6 to 15), the lunch stay in seconds (20 to 40), `pick`, a number in [0, 1) that picks the first kind of the trip, and `game`, a number in [0, 1) that sets the game time of a waiter. `office.js` uses `hash(terminalId, 1e9)` as the seed.
- A meeting room also has `table` and `seats`, and `session` when it holds a meeting. Without meetings, the office has one empty room with the id `meeting`.
- A desk has `id` (the pane id), `roomId`, `podId`, `terminalId`, `x`, `z`, `focused`, `label`, `cwd`, `title`, `status`, and `agent` (`null` for a shell pane). An orchestrator desk also has `away`: its seat at the head of the meeting table.
- Pass the previous office as `prev`. Then each subagent keeps its seat from one update to the next.
- `demoSnapshot(tick)` and `demoMeetings(tick)` return the fake data for one tick. The page moves one tick each second. The same tick always gives the same data. Two agents in different rooms (`w2:p2` and `w3:p3`) idle for 110 s and 200 s in each cycle, so they take breaks. A kitchen trip needs about 100 s, a party trip less, and a lunch up to 135 s. The demo party room has a ping-pong table and a chess table, so `w2:p2` waits at a table and `w3:p3` joins it.
- `readMeetings(projects, cwds, now)` returns `[{ sessionId, cwd, agents: [{ agentId, label, phase, model, workflow, runId }] }]`. It gives one entry for each herdr claude cwd whose Claude session has subagents that still run.
- `GET /events` is SSE. A message is `{ online: true, snapshot, meetings }`, or `{ online: false, snapshot: null, error }` when the herdr request fails.
- The bridge sends a message only when its JSON changes. While a client is connected, it polls `session.snapshot` every 500 ms and reads meetings every 2000 ms.
- `POST /action` takes the body `{"type":"focus","pane_id":"w<id>:p<id>"}` and the header `x-office-token`. It sends `pane.focus` to herdr and returns 200 `{ ok: true }`.
- `POST /action` also takes `{"type":"prompt","pane_id":"w<id>:p<id>","text":"..."}`, where `text` has at least one non-space character. It sends `agent.prompt` with `{ target: pane_id, text }` to herdr and returns 200 `{ ok: true }`. A prompt does not bring the terminal to the front. The panel of an agent desk sends it from the message field (`#say`).
- After a successful `pane.focus`, the bridge brings the terminal app to the front with `open -b <bundle id>`. `raiser()` detects the id at each raise: `pgrep -x herdr`, then `ps eww` for each pid, and `bundleIdsIn()` keeps only `__CFBundleIdentifier`. One id wins. With none or many, it opens the start pick. The `import.meta.main` block makes the start pick with the same detection. One id wins. Else `pickTerminal()` shows a numbered selector on a TTY, else it takes the first id, else WezTerm. So a move of herdr to another terminal needs no restart. The raise does not select the herdr window or tab, and it works on macOS only. `startBridge()` runs it only through its `raise` option. The tests pass a stub. A failed `open` or a failed detection logs and does not change the reply.
- Command mode is on in a single executable, or with `--command` for plain `node`. The bridge then listens on a free port unless `PORT` is set, and prints the URL line `herdr-office: <url>`. Then it opens the URL with `openUrl()`: `open` on the Mac, `chromium --app` then `xdg-open` on Linux. `HERDR_OFFICE_NO_OPEN=1` turns the open step off. The bridge exits 30 s after it has had no `/events` client (`quitMs`). `--version` prints the version and exits. On Linux the bridge skips the terminal pick and the raise (`raise` is `null`).
- Each start of the bridge makes a new token. The page reloads when its `/events` stream reconnects, so it gets the new token.
- `GET /messages?pane=<pane_id>` needs the header `x-office-token`. It uses the last good snapshot of the poll and sends no request to herdr. A bad token or `Host` gives 403, a bad pane id gives 400, no snapshot gives 503, an unknown pane gives 404, a `pane.agent` with no reader (only `claude` and `codex` have one) gives 404, a reader with a `null` folder (`claudeDir` or `codexDir`) gives 503, no transcript gives 404, and else 200 `{ messages }`. Each JSON reply has `cache-control: no-store`.
- `readMessages(projects, pane, limit = 100)` returns the last `limit` messages of a snapshot pane, or `null`. Only a pane with `agent === 'claude'` has them. With `agent_session.kind === 'id'` and a uuid, it finds `<id>.jsonl` in the cwd folder, then in each folder of `projects`. A valid uuid that it does not find gives `null`. Only a missing or bad id takes the fallback: the newest transcript of the cwd folder whose cwd matches. It reads only the last 512 KB. A read error gives `null`.
- `readCodexMessages(sessions, pane, limit = 100)` returns the last `limit` messages of a snapshot pane, or `null`. `sessions` is `$CODEX_HOME/sessions`. Only a pane with `agent === 'codex'` has them. With `agent_session.kind === 'id'` and a uuid, it finds the rollout whose name ends with `-<id>.jsonl` in any date folder. A valid uuid that it does not find gives `null`. Only a missing or bad id takes the fallback: the newest rollout whose first line (`session_meta`) has the cwd of the pane and a string `source` (a subagent thread has an object there). It reads only the last 512 KB. A read error gives `null`.
- `messagesIn(text)` turns JSONL text into `[{ role: 'user' | 'agent' | 'subagent', text, from? }]` in file order. It keeps user prompts and agent text blocks. It drops thinking, tool calls, tool results, `isSidechain`, `isCompactSummary`, and wrapper texts (`<task-notification`, `<command-name`, `<command-message`, `<local-command-stdout`, `<bash-input`, `<bash-stdout`). It drops each `isMeta` entry, except a user entry with `origin.kind === 'peer'`. A user text that starts with `Another Claude session sent a message` gives one `subagent` message for each `<teammate-message>`, `<agent-message>`, or `<cross-session-message>` block. `from` is `teammate_id`, else `from-name`, else `from`. The text is the first string of `result`, `summary`, `message`, or `content` of a JSON body, with `failed: <failureReason>` first. A leading `[harness: ...]` line and the empty line after it are dropped from each block. A hand-back gives its report after the line that ends with `The report follows:`. Else it is the trimmed body. The head line and the trailing note never show, and an empty block is skipped.
- `codexMessagesIn(text)` turns Codex rollout JSONL text into `[{ role: 'user' | 'agent', text }]` in file order. It keeps only `response_item` entries with `payload.type === 'message'`: the role `user` gives `user`, and `assistant` gives `agent`. It drops other roles, every `event_msg`, and every user block that starts with an injected tag (`environment_context`, `user_instructions`, `image`, `skill`, `turn_aborted`, `user_shell_command`, `subagent_notification`, `agent_message_board_notification`, `codex_internal_context`, `goal_context`, `external_*`, `recommended_plugins`, `hook_prompt`) or with `# AGENTS.md instructions`. The text is the `input_text` and `output_text` blocks joined with `\n`, and a message with no text is skipped.
- `POST /action` errors: a bad token or `Host` gives 403, a body over 4 KB gives 413, other bad input gives 400, and a herdr error gives 502.

## Scene conventions

- The floor is x/z, and y is up. North is -z, south is +z, and the west outer wall is at x = 0.
- The camera looks from +x +z. `OFFSET` is (100, 100, 100), and rotation is off.
- The north and west outer walls are the far walls: full height, with windows (`outer()`). The south and east outer walls face the camera, and `stub()` cuts them to 0.5 high.
- Rooms stand in bands: a north row, a corridor, and a south row. A north-row room has its door in its south wall. A south-row room has its door in its north wall (`room.door.side`).
- A row with 4 or more spare width keeps its room widths, and a terrace (a garden) fills the rest of the row (INTENT.md decision 26). `build()` draws the grass and one glass wall on each edge of a terrace to a room or a corridor. Two terraces back to back share their edge with no wall. The north outer wall skips a first-row terrace, and a low hedge stands there. A last-row terrace keeps the south stub.
- The cross corridor runs along the +x side. The lobby is the last room. It touches the south outer wall, and the entrance is in that wall.
- A desk is 2 x 1.5 around `(d.x, d.z)`. The monitor faces +z, toward the camera. The worker sits on the +z side.
- A prop from `at()` in `decor.js` faces +z before its turn (`rot` 1: +x, 2: -z, 3: -x). A meeting seat faces -z before its turn. `seats[0]` is the head seat at the -x end of the table.
- `box(parent, [w, h, d], [x, y, z], color)` puts `y` at the base of the box, not at its center.
- `box()` with a color string uses one cached material for each color (`MATS` in `decor.js`). Never change the color of a cached material, because every box with that color changes. For a color that changes in place, pass `fresh(color)` from `office.js`.
- `bake()` merges the static meshes into one mesh for each material after each build. It skips each object in `live` and all children of that object. Add to `live` each object whose color, visibility, position, or rotation changes after the build.
- Each door is closed (hinge angle 0). Only a walker on a trip opens a door: its own room door and the door of its target room, the kitchen, the party room, or the room of a game table (`opens()`). A walker to a game table in its own room opens no door. `pose()` adds the ids to `ajar` each frame, and `swing()` turns each door toward open (-1.1, into the room) or closed. A door takes 0.25 s from closed to open, from the frame time, at any frame rate. The hinge is in `live`, and the room view has `hinge`. The angle lives in `doors` (by room id), outside `views`, so a rebuild keeps it. The doors of the meeting room and the lobby never open.
- `update()` calls `build()` only when the build signature `sig` changes. The signature holds the positions of rooms, pods, desks, and subagents, and the season.
- The build signature also holds the agent kind and `away` of each desk, the `rot` and `model` of each subagent, `office.terraces`, and the season.
- A status change updates materials and labels in place and never rebuilds the scene. If new geometry depends on a new field, add that field to the build signature.
- `build()` disposes each material without `userData.shared` and each merged geometry. Mark a material that must stay across builds with `shared()` from `office.js`.
- `night(on)` sets the light at each `update()`. With `on` (Halloween), it sets the castle night all day, and `?time` has no effect. Else the values come from `daylight(clock())`, and its 15:00 values are the reference day look (decision 9). Castle values: ambient `#7f8fb8` / ground `#2e2622` / 1.1, sun `#a9bce8` / 0.8, `SKY` color `#1d2540` / emissive `#141c33`, background `#0b0d1a`. Values at 15:00: ambient `#fff1dc` / `#7a6250` / 2, sun `#ffdcae` / 2.4, `SKY` `#a9d5ef` / `#55819e`, background `#181825`. The sun is off (`castShadow` false) when `sunPower` is 0.
- The candle flames, halos, and floor pools are in `live`. The glow texture `blob` has `userData.shared`, so `build()` does not dispose such a map. All pools use one geometry (`poolGeo`). The candles add no three.js light, because a light shines through walls.
- The candle flames glow in orange only (`#ff6a1a` to `#ffae42`, halo `#ff9a40`, pool `#ff8a30`). This is the exception to "no prop glows" (INTENT.md decision 32).
- The tree bulbs glow (a second exception, like the candle flames). The ornaments of `xmasTree` use one unlit `MeshBasicMaterial` for each color (white `#f4f1ea`, silver `#c9ccd3`, violet `#8b5cf6`, blue `#4a6fa8`), with `userData` `shared` and `bulb`. `lightBulbs()` in `build()`, before `bake()`, adds one additive halo sprite (0.35, depth test on) 0.06 in front of each bulb face, in `live` and in `bulbs`. The phase of a bulb comes from `rng` seeded with the tree position. `bulbLights(t)` sets each halo opacity with `twinkle()`, at half swing with reduce motion. The bulbs add no three.js light.
- `lightning(t)` runs each frame in the castle night (the Halloween season). The clock night at 23:00 has no lightning. A strike comes after the wait of `lightningPlan()`. In the castle night, without reduce motion, it writes the ambient intensity, the `SKY` emissive, and the background each frame (the night value plus the flash). A change of one of these values in `CASTLE` needs the same change in `lightning()`. With reduce motion (`prefers-reduced-motion`), it writes the night values once, then nothing (when a strike is in progress), no lightning shows, and the flames flicker at half strength.
- With Halloween, `build()` makes one group for each ghost of `ghosts(office.bounds)` (`ghost()`), in `live`, with cached colors: the sheet `#f4f4f8` and the eyes `#1a1a1a`. The eyes face +z before the turn. Each frame, `haunt(t)` sets the position from `ghostAt()` and eases `rotation.y` toward `atan2(dx, dz)`. With reduce motion it passes `t / 2`, so a ghost floats and bobs at half speed. A ghost is opaque, because a see-through body looks like an `unknown` worker (opacity 0.35). It has no view, no badge, no status, and no three.js light. Its one label is the balloon `Boohooo!` (class `boo`), and it is not in `tags`, so `declutter()` never hides it. The click handler gives each ghost a box 0.56 x 1.2 x 0.56 from its base, and the nearest hit wins. A ghost hit sets `until` to 2 s after the click and opens no panel. `haunt(t)` shows the balloon while `t < until`.
- In winter, `build()` makes the flakes of each terrace and of `outdoors(office.bounds)` with `snowflakes()`, and one `InstancedMesh` of white `#ffffff` boxes of 0.06 for all of them. The mesh is in `live` and has `frustumCulled = false`. Its geometry and material are shared, and `build()` calls `dispose()` on the mesh to free the instance buffer. Outside winter there is no flake mesh. `snowfall(t)` writes each instance matrix each frame with `flakeAt()`. With reduce motion it uses half the time, so the snow falls at half speed. A flake passes through each garden prop.
- `views` maps each room, pod, desk, and subagent id to the objects that show its state. `pose()` runs each frame for each view that has a `desk`.
- Each `DECOR` function gets a group at the room corner, so decor uses room-local coordinates. `terrace()` gets a group at the terrace corner. `placer()` puts a prop on free floor only, and skips a prop that does not fit.
- `COLOR` in `office.js` is for 3D meshes. It uses a strong yellow `#ffd43b` for `working`. `STATUS_COLOR` in `model.js` holds the herdr theme colors for HTML: the HUD, the list, the badges, and the door signs. For `blocked`, it uses a strong red `#fa5252` instead of the herdr pink-red, in the HTML and in 3D.
- `declutter()` hides a label that overlaps a label with a higher priority. Agent badges come first by status rank, then door signs by status rank. It sets `visibility`, because `CSS2DRenderer` owns `display`.
- Add each new label to `tags` in `update()`. A label that is not in `tags` never hides. The ghost balloon stays out of `tags` on purpose, because it shows for 2 s only.
- Put text into a label, the HUD, the panel, or the chat window with `textContent` only. Pane labels, titles, cwds, subagent labels, and transcript text come from outside the page, so never use `innerHTML`.
- Only a desk worker with the status `idle` takes breaks. An orchestrator with `away`, a subagent, and a shell desk never do.
- A trip belongs to `trips` (by desk id), not to a view, so a rebuild of the scene for a new subagent does not end it. `update()` also builds `lay`, the route inputs: the position, the size, the door, and the pods of each workspace room, of the kitchen, and of the party room, the cross corridor, and the id, position, room, and pod of each desk. A change of `lay` clears `trips` and `claimed`. A meeting start or end ends no trip while the floor plan stays the same. A meeting room that gets wider (9 or more subagents in the demo plan) and a second meeting at the same time move the rooms, so they end every trip. A desk that gets `away` or loses its agent loses its trip at once (`endBreak()`, with the frame time, so the game of its partner ends). In the first case the worker moves to the seat. In the second case no worker is left. A worker takes a free counter spot, kitchen chair, dance spot, or game place from `claimed` when the trip starts and frees it when the trip ends. With no free spot of any kind the worker keeps browsing.
- A worker on a trip stays a child of its desk group. `stroll()` sets its local position from the route (the world point minus the desk position) and eases `rotation.y` toward a target heading. The target is `atan2(-dx, -dz)` on the way out, `atan2(dx, dz)` on the way back and in the run, and 0 (the counter) during a kitchen stay. So the worker faces the way it moves, and the counter during a kitchen stay. The seated legs (`sit`) and the standing legs (`stand`, two hip pivots) switch by visibility. The mug shows after the kitchen. In the stay of a lunch trip, the worker sits on its kitchen chair: the group is at the chair point (y 0.5, no 0.4 offset), the target heading is `rot * π / 2`, `sit` and the `plate` show, and `stand` and the mug hide. The right arm goes from 1.2 to 2.0 and back in 1 s, every 3 to 5 s, with the period and the phase from a hash of the desk id. Each arm angle stays at 2.0 or less. The plate is made after `mats`, so it never fades. In the stay of a game trip, the group is at the place (y 0.5, no 0.4 offset), and the target heading is `rot * π / 2`. A chess player sits (`sit`). A ping-pong player stands and shows the `paddle` (`#b06a4f`, in the right hand, made after `mats`). A waiter keeps its arms down. While `play`, the chess player in turn (the west player in even turns of 3 to 5 s from `begin`) reaches to the board, and a ping-pong player turns its body by up to 0.35 rad, back before each hit and through after it, with the right arm at 1.4 and at 1.5 at the hit. So the paddle stays above the table top. Each arm angle stays at 1.5 or less. The run back shows the status parts that work while standing: the beacon, the paper, and the transparency.
- A dancer is a worker in the stay of a trip to the party room. `stroll()` turns it to the booth: heading 0 when the booth has a smaller z, else π, with a sway of ±0.35. It hops from foot to foot, sways its hips, and pumps its arms in turn. Each arm angle stays at 1.5 or less, so no hand goes above the shoulder (a raised hand means `blocked`). The tempo (1.6 to 2.4 steps a second) and the phase come from a hash of the desk id. A dancer gets no mug.
- `partyLights()` in `office.js` builds the moving parts of the party room, not `decor.js`: the dance floor tiles, the disco ball with its light beams, and two speakers beside the booth. The ball and the speakers are in `live`. The tiles merge in `bake()`, so `disco()` changes only the colors of their 3 own materials.
- The party room parts move only while a worker dances (`dancing`). Then the tiles change color twice a second, the ball and the beams turn, and the speakers pulse on 2 beats a second. Else the tiles are dark, the beams hide, the ball stops, and each scale is 1. The colors are magenta `#e040fb`, violet `#8b5cf6`, and white only. The room has no three.js light source, because a light shines through walls.
- `rally()` in `office.js` moves the ping-pong balls. `build()` makes one white ball for each ping-pong table, in `live` and hidden. While both players of the table `play`, the ball crosses from paddle to paddle in 0.8 s (`HIT`), along an arc, and bounces once on the half of the receiver. The west player serves at `begin`. Else the ball hides.
- `pose()` raises `moving` while a worker walks. The loop then clears `seen` four times a second, so `declutter()` follows the walking badges.
- An idle worker at the desk shows a fake page or a video on the screen. `browse()` draws into the same canvas as `typing()` and draws only when the picture changes. The idle green stays the main color of the picture, and no picture color is near a status color. A worker on a trip shows the plain idle green.
- The look of a worker (skin, hair, trousers, accessory) comes from a hash of its `terminalId` (for a subagent, its agent id). The shirt color comes from `SHIRT`, by agent kind or by model family. A look change must not change the shirt. In winter each worker wears a knit sweater over the shirt color (`worker()` reads the `winter` flag that `build()` sets). The torso and the arm boxes keep the shirt color. The knit is one material for each worker: off-white `#f4f1ea`, or navy `#2f3b52` when the HSL lightness of the shirt, in sRGB, is 0.8 or more (the Codex shirt). It has 13 boxes: a hem, a chest band, a yoke on top of the torso, four dots on the back and front, two dots on the sides, and a cuff and a ring in each arm group. They fade with the body.

## herdr facts the code depends on

- herdr reads one JSON line on each socket connection, writes one reply line, and closes the socket. `herdrRequest()` opens a new connection for each request.
- Each request needs `"params"`, also when it is empty. Without it, herdr returns `invalid_request`.
- The statuses rank `blocked` 4, `done` 3, `working` 2, `idle` 1, `unknown` 0. A tab or a workspace shows the highest rank of its panes.
- The model uses the `agent_status` that herdr sends for each tab and workspace. It calls `rollup()` only when herdr does not send one.
- `done` is the herdr state `Idle` with `seen == false`: the agent finished, and nobody saw the pane after that. The first idle state of a new agent is `idle`, not `done`.
- `unknown` is a plain shell, an unknown program, a new agent in its first 3 s, or a released agent.
- `pane.focus` marks the whole tab as seen, so each `done` desk in that tab turns `idle`. The panel shows this warning.
- `agent.prompt` types the text and presses Enter. It refuses a blocked agent with `agent_blocked` and sends nothing. The office relies on this, so a message never answers a blocked question.

## Safety rules

- Never send a mutating request to the live herdr socket from a test. Tests use fake unix sockets only.
- Always pass `sock` to `startBridge()` and `herdrRequest()` in a test. herdr sets `HERDR_SOCKET_PATH` in each pane, so `socketPath()` gives the live socket.
- macOS limits a unix socket path to 104 bytes. `test/bridge.test.mjs` changes its cwd to a temp folder and uses short relative names (`h1.sock`). Use the same method for a new fake socket.
- During a check in live mode, never click "Focus in herdr" or "Focus orchestrator". The click switches herdr to that pane and marks the tab as seen. Use `?demo`, where the button is disabled.
- During a check in live mode, never send a message from the panel. herdr types it into a live agent of the user. Use `?demo`, where the field is disabled, or a fake herdr socket (`docs/testing.md` "Visual check in the browser").
- Never run bare `herdr`, because it opens the interactive client. Use read-only commands only, for example `herdr agent list` or `herdr api schema --json`.
- Treat `~/.claude` and `~/.codex` as read-only. The tests use a fake projects tree and a fake Codex sessions tree in their temp folder.
- Meetings carry metadata only. The bridge reads folder listings, `meta.json` files, and `journal.jsonl`.
- The bridge also reads the start of a session transcript for its cwd. From the end of a subagent transcript, it takes only the end marker and a `claude-*` model id. For `GET /messages`, it also reads the last 512 KB of a session transcript. For a codex pane, it reads the first line of each rollout (its cwd and source) and the last 512 KB of one rollout.
- Transcript text goes to the browser only through `GET /messages`: the user prompts and the agent replies of one claude or codex pane, on request, behind the token. Never put transcript text into the `/events` stream. `messagesIn()` drops thinking, tool calls, tool results, and wrapper texts. `codexMessagesIn()` drops developer texts, reasoning, tool calls, tool output, `event_msg` entries, and the injected texts. The test of each must check that their `SECRET` text is not in the output. A new meeting field must still come from metadata, and its test must check that the `SECRET` text is not in the output.
- Never copy live data from the herdr session of the user into a repo file. This includes workspace labels, project names, terminal titles, pane IDs, and home paths. Use generic examples like `w1:p1`, "api", or "web".
- Keep each bridge guard: listen on 127.0.0.1 only, the `Host` check, the `x-office-token` check (also on `GET /messages`), `x-frame-options: DENY`, `cache-control: no-store`, and no CORS headers. `test/bridge.test.mjs` checks each guard except the listen address.
- Stop each server that you start. Start a check bridge on its own port: `PORT=4848 npm start`. Then a check never stops the user's bridge on 4747. To stop the check bridge:
  1. Get the PID with `lsof -nP -tiTCP:4848 -sTCP:LISTEN`. Do not use `$!`, because it can give the PID of a wrapper shell.
  2. Kill that PID.
  3. Run the `lsof` command again to make sure that the port is free.

## Visual checks

The repo has no browser harness. Earlier agents ran headless Chrome with `--remote-debugging-pipe` and sent CDP commands, because the Chrome extension was not connected. To zoom, they dispatched a `WheelEvent` on the canvas from a page eval. The controls zoom to the pointer position.
